# Feature: จองคิวตรวจสุขภาพ (Booking)
Spec ID: SPEC-BKG-001 | Source: SRS v0.3 ข้อ 3.1 (FR-BKG), ข้อ 3.3, ข้อ 3.4 | Use case: UC-01
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-09

## Goal
ผู้รับบริการที่ยืนยันตัวตนแล้ว เลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพ แล้วได้รับหมายเลขคิว
ยืนยันภายใน 3 นาที โดยโรงพยาบาลกระจายผู้รับบริการได้สมดุลตามโควตาของแต่ละช่วงเวลา

## Scope
### In scope
- แสดงวันและช่วงเวลาที่ว่างภายใน 30 วันข้างหน้า พร้อมจำนวนที่นั่งคงเหลือ
- จองคิว 1 รายการต่อผู้รับบริการต่อวัน
- ออกหมายเลขคิว และส่งข้อความยืนยันผ่านระบบแจ้งเตือน
### Out of scope
- ยกเลิก / เลื่อนคิว (UC-02) | ชำระค่าบริการ (UC-03) | จัดการตารางคิวและโควตา (UC-09)
- ยืนยันตัวตน (UC-13) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)

## Constraints
- CON-TECH-01 ใช้ฐานข้อมูล MySQL ตามมาตรฐานฝ่าย IT ของโรงพยาบาล
- DOM-PDPA-01 บันทึก audit log ทุกครั้งที่เข้าถึงข้อมูลสุขภาพ (ผู้เข้าถึง, เวลา, รหัสผู้รับบริการ)
  เก็บไม่น้อยกว่า 1 ปี
- IF-IDP-01 ต้องได้รับผลยืนยันตัวตนจากระบบยืนยันตัวตนก่อนเข้าถึงข้อมูลผู้รับบริการ
- IF-HIS-01 ค้นข้อมูลผู้รับบริการจาก HIS ด้วยเลขบัตรประชาชน แล้วอ้างอิงภายในระบบด้วย HN
  ไม่เก็บเลขบัตรประชาชนในตารางการจอง
- IF-NOT-01 ส่งข้อความยืนยันผ่านระบบแจ้งเตือน SMS/LINE แบบ asynchronous
  (การจองต้องไม่รอผลการส่งข้อความ)

## Requirements
- FR-BKG-01 ระบบต้องแสดงช่วงเวลาที่ว่างของแต่ละวันภายใน 30 วันข้างหน้า
  พร้อมจำนวนที่นั่งคงเหลือของแต่ละช่วงเวลา
- FR-BKG-02 ระบบต้องปฏิเสธการจอง เมื่อผู้รับบริการมีคิวที่ยังไม่ได้ใช้ในวันเดียวกัน
  และแสดงหมายเลขคิวเดิม
- FR-BKG-03 เมื่อช่วงเวลาที่เลือกเต็มระหว่างการยืนยัน ระบบต้องแจ้งเตือน
  และเสนอช่วงเวลาใกล้เคียง 3 ตัวเลือก โดยไม่สร้างรายการจอง        <- UC-01 exception 5a
- FR-BKG-04 เมื่อยืนยันสำเร็จ ระบบต้องบันทึกการจอง ตัดจำนวนที่นั่งของช่วงเวลานั้น
  ออกหมายเลขคิว และส่งคำขอส่งข้อความยืนยัน                          <- UC-01 main flow ขั้น 6
- FR-BKG-05 หากส่งข้อความยืนยันไม่สำเร็จ ระบบต้องยังคงบันทึกการจอง
  แสดงหมายเลขคิวบนหน้าจอ และนำข้อความเข้าคิวส่งซ้ำ                  <- UC-01 exception 5b
- FR-BKG-06 เมื่อผู้รับบริการเปลี่ยนแพ็กเกจระหว่างเลือกเวลา ระบบต้องคำนวณ
  ช่วงเวลาที่ว่างใหม่ตามแพ็กเกจที่เลือก                                <- UC-01 alternative 3a

## Quality Requirements
- NFR-PERF-01 การค้นหาช่วงเวลาว่าง: เวลาตอบสนอง p95 <= 2 วินาที ที่ผู้ใช้พร้อมกัน 200 คน
- NFR-SEC-01 ข้อมูลการจองเข้ารหัสขณะรับส่งด้วย TLS 1.2 ขึ้นไป
- NFR-REL-02 ข้อความที่ส่งไม่สำเร็จ ต้องถูกส่งซ้ำภายใน 5 นาที
- NFR-USE-01 ผู้ใช้ใหม่จองคิวสำเร็จภายใน 3 นาที โดยผู้ทดสอบ 8 ใน 10 คน
  ทำสำเร็จโดยไม่ต้องขอความช่วยเหลือ

## Acceptance Criteria
- [ ] AC-BKG-01 (FR-BKG-04)
      Given ยืนยันตัวตนแล้ว และช่วง 09.00 น. มีที่นั่งว่าง 1 ที่
      When  ยืนยันการจอง
      Then  บันทึกสำเร็จ แสดงหมายเลขคิว และที่นั่งว่างของช่วงนั้นเป็น 0
- [ ] AC-BKG-02 (FR-BKG-02)
      Given มีคิวที่ยังไม่ได้ใช้ในวันเดียวกัน
      When  จองคิวใหม่ในวันเดียวกัน
      Then  ปฏิเสธ และแสดงหมายเลขคิวเดิม
- [ ] AC-BKG-03 (FR-BKG-03)
      Given ช่วงเวลาที่เลือกเหลือ 1 ที่ และผู้ใช้อีกคนยืนยันก่อน
      When  ผู้ใช้กดยืนยัน
      Then  แจ้ง "ช่วงเวลาเต็ม" แสดงช่วงเวลาใกล้เคียง 3 ตัวเลือก และไม่มีรายการจองซ้อนเกิดขึ้น
- [ ] AC-BKG-04 (FR-BKG-05, NFR-REL-02)
      Given ระบบแจ้งเตือนไม่ตอบสนอง
      When  ยืนยันการจอง
      Then  การจองถูกบันทึก แสดงหมายเลขคิว และมีรายการในคิวส่งซ้ำที่กำหนดส่งภายใน 5 นาที
- [ ] AC-BKG-05 (NFR-PERF-01)
      Given ผู้ใช้พร้อมกัน 200 คน
      When  ค้นหาช่วงเวลาว่าง
      Then  p95 ของเวลาตอบสนอง <= 2 วินาที
- [ ] AC-BKG-06 (DOM-PDPA-01)
      Given มีการเปิดดูข้อมูลการจองของผู้รับบริการ
      When  การเข้าถึงเสร็จสิ้น
      Then  มี audit log ที่ระบุผู้เข้าถึง เวลา และรหัสผู้รับบริการ
